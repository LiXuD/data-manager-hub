# UAPI 指定日期程序员历史接口实施与验收

## 1. 官方契约

- 文档：`https://uapis.cn/docs/api-reference/get-history-programmer`
- 厂商端点：`GET https://uapis.cn/api/v1/history/programmer`
- 请求参数：
  - `month`：必填整数，范围 1～12；
  - `day`：必填整数，范围 1～31。
- 成功响应包含 `message`、`date` 和 `events`；事件包含年份、标题、描述、分类、标签、重要性和来源。

平台接口编码为 `PROGRAMMER_HISTORY_BY_DATE`，数据类型编码为
`programmer_history_by_date`。厂商端点免费，但仍配置零元计费方案，
保证调用必须经过 Billing 策略解析和事件入账，不使用绕过或降级价格。

## 2. 全链路验收口径

```text
浏览器登录
  → 接口管理页查看接口与契约
  → 接口权限申请并提交
  → 审批人认领并批准
  → 数据测试页输入 month/day
  → Gateway API Key 鉴权
  → Access 接口/产品/缓存授权
  → Masterdata 解析 UAPI 厂商配置
  → UAPI 真实 GET 请求
  → 响应契约校验
  → Kafka 调用记录
  → Billing 零元事件与日聚合
  → 审批动作审计
```

正向场景使用 `month=4`、`day=4`，应返回 `date=04-04`，并包含
“微软公司成立”等真实事件。负向场景至少覆盖缺少必填参数、`month=13`
以及未获接口授权，分别在契约或权限边界失败，且不得产生厂商成功调用事实。

## 3. 数据库变更

V029 独立创建数据类型、接口、请求/响应契约、UAPI 厂商配置和零元计费方案。
迁移发现同编码手工配置时失败关闭，不覆盖未知数据。回滚仅在没有权限申请、
授权、调用记录、计费事件和额外计费方案时执行；已有业务事实时必须采用前向修复。

## 4. 真实运行验收记录

验收在独立 PostgreSQL 数据库 `codex_uapi_history_e2e` 中执行，浏览器访问真实
Vite 页面，后端六个服务经 Gateway 调用真实 UAPI；没有 mock 厂商响应。

- 申请单 `APA20260725000559F2F7FABE` 由普通用户在页面提交，Flowable 流程版本
  为 1；管理员在页面认领并批准后，授权台账状态为 `ACTIVE`，审批缓存上限为 2 天。
- 审批前通过数据测试页调用返回 HTTP 403，错误为“API Key没有访问该接口的权限”。
- 审批后在页面输入整数 `month=4`、`day=4` 和 `cacheDays=2`，真实厂商请求返回
  HTTP 200、`date=04-04`，包含“微软公司成立。”和“网景通信公司成立。”。
- 首次平台调用记录 `req_bab558564fa84f7f` 为非缓存调用，响应契约校验通过；
  第二次记录 `req_470490049dcc4db2` 命中首次记录，耗时从 769ms 降至 19ms。
- 两次调用均进入 `billing_event` 和 `billing_daily`；首次是零元可计费事件，
  缓存命中按方案记为免费事件，日聚合调用数和成功数均为 2。
- `month=413` 被请求契约以 HTTP 400 拒绝；`cacheDays=3` 被审批上限以 HTTP 403
  拒绝；缺少 `day` 被页面必填校验拦截。三个失败场景均未新增调用或计费事实。
- 已产生审批、授权、调用和计费事实后尝试回滚 V029，回滚脚本按设计失败关闭。

## 5. 验收中发现并修复的问题

真实页面链路暴露出三个既有集成缺口，并以最小改动修复：

1. 数据类型查询把 `CommonStatus` 枚举对象直接交给数据库，导致页面拿不到启用的
   数据类型；现统一使用持久化编码 `active`，并覆盖分页列表和全部列表测试。
2. 页面创建调用方时未写入当前租户，导致普通用户无法在申请页选择该调用方；
   现由服务端强制写入 `UserContext` 租户。浏览器新建验收调用方后，数据库确认
   `tenant_id=91001`，随后已通过页面删除该临时记录。
3. 数据测试页只识别 `number`，未把标准契约类型 `integer` 映射为数值输入，首次
   请求因字符串参数被后端拒绝；修复后页面渲染数值控件并提交 JSON 整数，真实
   调用成功。
4. 数据库脚本曾在 V027 已执行后无条件阻止所有后续回滚；现仅当本次回滚集合实际
   包含不可逆的 V027 时阻断。独立空库已验证 V029 更新、无事实回滚、重新应用和
   重复更新；回滚三步跨越 V027 时仍按设计拒绝。
